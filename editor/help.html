Getting started

The Slipr Editor creates and changes Slipr shows in the browser. You pick layouts, fill in fields, add images and write the reader layer; the preview shows the result exactly as the viewer will. You never have to edit JSON by hand.

Browser: use Google Chrome or Microsoft Edge. Opening, creating and saving show folders, adding images, and presenting a show from a folder need the File System Access API, which only these browsers have. In other browsers you can look at a show opened by its address, but not save it.

Without a show, the editor opens on the start screen:

  • Open show folder…: pick a folder that contains a show.json.
  • New show…: start a show from a template in an empty folder.
  • Recent shows: the folders you opened before in this browser. One click reopens a show.
  • The demo show link opens the example show that comes with Slipr. Use it to look around.

This manual is always one click away: the ? Help button in the toolbar, or F1, which opens the section for the tab you are working in.

Key ideas

A Slipr show is written once and serves two very different experiences:

Audience mode
The slideshow for a room: linear, concise and high level, with builds, transitions, an agenda and speaker notes. This is the slide itself, edited in the Slide tab.
Reader mode
For one person reading at their own pace: the slides plus a detailed reader layer of text, panels, tabs, callouts, diagrams (Mermaid), images with hotspots and embedded pages, tailored to the reader's profile and chosen depth. Edited in the Reader tab.

Tip: keep the slide short and put the depth in the reader layer. A slide with three words and a picture can carry pages of explanation for readers.

TermMeaning
ShowA presentation: a folder with show.json and an images/ folder. It can live anywhere on your disk.
TemplateThe look and feel: colours, fonts, illustrations and a set of layouts. Every show uses one template. Slides contain no styling; change the template and the whole show changes with it.
LayoutA slide format in the template, such as Title, Section, Title + bullets, Two columns, Full image or Diagram.
SlotA place in a layout that you fill: a title, a body text, an image, a quote, a diagram, a set of cards. The Slide tab shows one field per slot.
Reader blockOne piece of the reader layer of a slide: text, a collapsible panel, a callout, tabs, a diagram (Mermaid), an image with hotspots, an embedded page or a link to another slide.
ChapterA group of slides. Chapters drive the agenda in audience mode and the contents in reader mode.
ProfileA kind of reader, such as Developer or Manager. Reader blocks can be meant for some profiles only.
DepthHow detailed a reader block is: 1 Essential, 2 Standard, 3 Deep dive. Readers choose how deep they want to go.
Reading routeA curated path through the show, for example a five-minute overview.
GlossaryTerms with definitions. In reader mode a referenced term opens a popup with its definition. See Glossary.

The screen

  1. Toolbar (top): the show's title with a dot (●) when there are unsaved changes, undo and redo, find and replace, open, new, save and export, the show grid, Present and Read, this help, and the theme. In a narrow window it wraps onto two lines.
  2. Slide list (left): every slide in order, with a Go to slide box, and ⚙ Show for the show settings.
  3. Inspector (middle): the Slide tab for the audience layer and the Reader tab for the reader layer of the selected slide, or the show settings.
  4. Preview (right): the selected slide as the audience or a reader will see it, and any problems with it.

Light or dark

The theme menu at the end of the toolbar switches the editor between ☀ Light, ☾ Dark and ◐ System, which follows your computer's light or dark setting. The choice is remembered in this browser, and this manual follows it too. It only changes the editor: slides always show in their template's own colours.

Messages such as Saved appear in a bar under the toolbar.

Open, create and save

Open a show

Click Open… and choose the folder that contains show.json. The browser asks once whether the editor may read and change that folder; allow it. The editor's address becomes editor/?folder=…: you can bookmark and reload it. After a browser restart the editor may ask again; click Allow access.

Create a show

  1. Click New….
  2. Enter a title and choose a template.
  3. Pick an empty folder. The editor writes show.json with a title slide, and an empty images/ folder.

Save

Press Ctrl+S or click Save. The editor writes show.json neatly formatted and always in the same order, so if you keep shows in git, a change shows up as a small difference. The first save of a hand-written show.json reformats it once.

While there are unsaved changes, a dot (●) follows the title and the browser warns you before you close the tab. The editor does not save automatically yet, so save regularly.

Shows opened by address

A show can also be opened by its web address, like the demo (editor/?show=…). The first time you save such a show, or add an image to it, the editor asks you to pick its folder on disk and checks that it holds the same show.

Templates of shows elsewhere on disk

If a show refers to its template by a path that leaves the show folder, the editor uses the template with that name from Slipr's own templates/ folder, and a message says so. New shows always refer to their template that way.

Show grid

The show grid shows all slides at once, as thumbnails grouped by chapter. Where the slide list is for working on one slide, the grid is for the structure of the show: rearranging, regrouping into chapters, and tidying up many slides at once.

When to use it

  • Reordering a long show, or moving a whole chapter.
  • Putting slides into chapters, or splitting a chapter.
  • Hiding, duplicating or deleting several slides in one go, for example turning the last five slides into backup slides.
  • Spotting problems: every slide with an error or warning is marked.

Open and close

Click ▦ Grid in the toolbar or ▦ above the slide list. The slide you were on is selected. Back to editor closes the grid; so does Esc when nothing is selected (with a selection, the first Esc clears it). Double-click a slide, or press Enter, to close the grid and open that slide in the editor.

S, M and L at the top change the size of the thumbnails.

What you see

  • Slides in show order, each with its number, title and a thumbnail drawn by the same renderer as the preview.
  • Slides are grouped into chapters the way readers see them: consecutive slides of the same chapter form one group, with the chapter's title and slide count above it. Slides without a chapter are grouped under No chapter.
  • A group marked continued is a chapter that comes back later in the show, after slides of another chapter. Readers then see that chapter twice in the contents. Usually that's a mistake: drag the stray slides next to the rest of their chapter.
  • Badges on a slide: ◌ backup (hidden from audience mode), no reader (hidden from reader mode), ✖ errors and ⚠ warnings. Open the slide to see the problem under the preview.
  • Chapters that have no slides yet are listed under Chapters without slides.

Select slides

Click a slide to select it. Ctrl-click adds or removes one, Shift-click selects everything from the last clicked slide, Ctrl+A selects all. While slides are selected, a selection bar offers what you can do with them.

Keyboard

  • Arrow keys move through the slides and select the one you land on; ↑ / ↓ go to the slide above or below on screen.
  • Shift+arrows extend the selection; Ctrl+arrows move without selecting, and Space then adds or removes the focused slide.
  • Enter opens the focused slide in the editor; Esc clears the selection, or closes the grid.

Example: turn the last slides into a backup chapter

  1. Open the grid and click the first slide that should become backup material; Shift-click the last slide.
  2. Click + Chapter and type Backup.
  3. Click Hide from audience. The slides get the ◌ backup badge. In the presentation they come after the last slide, without numbers, for questions afterwards; readers find them in the Backup chapter.

Slide tab: the audience layer

The Slide tab shows one field for every slot of the slide's layout, followed by notes and options. A different layout gives a different form.

Choose a layout

Click the Layout button. A grid shows every layout of the template, each with this slide's content already in it, and says what switching would do:

  • Keeps all content: nothing is lost.
  • Hides Text: that field has no place in the new layout. Its content is kept out of sight and comes back when you switch back.
  • Brings back Photo: content hidden by an earlier switch returns.
  • Needs Agenda items: the new layout has a required field that is still empty.

Click a layout, or use the arrow keys and Enter. Esc closes the grid without changing anything.

One line, for titles, subtitles and captions.
Rich text and lists
Several lines with Markdown: **bold**, *italic*, bullets with - item.
Image
A preview, the file, the alt text and how the image fits its frame: as the layout decides, Fill the frame (may crop) or Show the whole image. See Images.

The quote and who said it.
Code
The language (for example js) and the code. Tab indents; press Esc and then Tab to leave the field.
Cards
Layouts with repeated items (columns, numbered boxes, key figures, image cards, people) get one group of fields per card. A counter such as 7 / 18 shows how much room a field has and turns yellow when the text is too long. Move cards with ▲ / ▼, remove one with 🗑, and add one with + Add card, up to the number the layout has room for.
Diagram
A Mermaid diagram definition (plain text) with an optional caption. Rendered directly in the browser as an interactive SVG on slides using the Diagram layout. See Diagrams (Mermaid).
Web page
On the Web page layout: the address (https, or a file in the show folder) and a title. While presenting: show the live page (clickable on the slide, no Load button) or show the fallback image (a screenshot; nothing is loaded, good for offline talks). A field marked No editor for this slot type yet (such as charts) can only be changed in show.json for now.

Speaker Notes
Private notes for the presenter. They appear in the presenter view (S in audience mode), never on the slide.

Puts the slide in a chapter, for the agenda and the reader contents. Create chapters in Show settings.

Comma-separated topics, used by reader search and "related" suggestions.

Hide from audience mode
The same as ◉ in the slide list: a reader-only slide.

Images

Every image field (on slides, in cards and in reader image blocks) accepts an image in three ways:

  • Choose… opens a file chooser.
  • Drop an image file onto the field.
  • Paste from the clipboard: Ctrl+V while the field has focus, or the Paste button. Ctrl+V anywhere outside a text field puts the image in the slide's first empty image field.

The editor copies the image into the show's images/ folder, named after the file (a pasted image after the slide) plus a short code. The same image added twice is stored once. Then it asks for alt text: a short description for people who cannot see the image, read aloud by screen readers and shown when the image cannot load. Leave it empty only for pure decoration. You can always change it later in the field.

Supported: PNG, JPEG, GIF, WebP, AVIF and SVG. Images over 3 MB get a warning, because they make the show slow to open: use a smaller or compressed version when you can.

Undo puts the previous image back. The editor never deletes image files; unused files simply stay in images/.

Extra images

A layout has its own places for pictures. When you need one more (a logo, an arrow pointing at a bullet, a screenshot next to the text), add it as an extra image: you put it anywhere on the slide and choose its size. Extra images sit in front of the layout's content and scale with the slide.

Tip: the template still decides the look of everything else. Use extra images for what the layout cannot do, not to rebuild a slide by hand.

Add one

  1. Select the slide. In the Slide tab, find Extra images and text (under the layout's fields).
  2. Drop an image on Add an extra image, paste one (Ctrl+V while it has focus, or Paste), or click Choose….
  3. Write the alt text in the dialog, as for any image.

The image appears in the middle of the slide, 30 % of the slide wide, with its own proportions. It is selected on the preview, ready to move.

Move and resize it on the preview

Extra images are placed on the preview in Audience mode. Each has a thin dashed outline; the selected one has a yellow outline and four corner handles.

An image always stays on the slide: you can't drag it past the edge. One drag, or a series of key presses, is one step for Ctrl+Z. The Slide tab shows each image's place and size as numbers (Left, Top, Width, Height, in % of the slide): type a value to place it exactly. ⌖ selects it on the preview. The other way round, selecting an image or text element on the preview highlights its settings in the Slide tab and scrolls them into view, ready to edit.

To save space, each image and text element is shown collapsed to one line: its number, a small picture or its text, and the ⌖ ▲ ▼ 🗑 buttons. Click the line (▸) to show its settings, and again to hide them. A new image or text, and the one you select on the preview, opens by itself.

Settings per image

Picture
Drop, paste or choose another picture to replace it; its place and size stay.
Alt text
What the image shows, for people who can't see it. Leave it empty only for decoration.
In audience mode
Visible from the start, or Appears on the next click, optionally with an effect such as fade-left. Images that appear on a click come after the slide's own steps (bullets, cards), in the order of the list.

In reader mode and elsewhere

  • Readers see the slide with its extra images in place. On a phone, where slides normally turn into flowing text, a slide with extra images stays a picture, so nothing lands on top of the text.
  • Extra images are included in Export as one file, and show in the show grid's thumbnails.
  • A show with extra images is saved in show format 0.2. That happens by itself; older versions of Slipr cannot open it.
  • Converting a PowerPoint deck: pictures that fit none of the layout's image places become extra images at the same place as in PowerPoint.

Text elements

A text element is a piece of text you place anywhere on the slide, in front of the layout: a badge (New), a label on a photo, a callout next to a chart, a pill with a date. You choose its place and size like an extra image, and you set its look yourself: font, size, colors, a fill, a border, rounded corners.

Tip: the colors offered first are the template's own, and the fonts and sizes are the template's unless you pick others. Stay with those and your text elements keep the show's house style.

Add one

  1. Select the slide. In the Slide tab, under Extra images and text, click + Add text.
  2. A box with the word Text appears in the middle of the slide, selected on the preview. Its text is selected in the Text field: just type.

The text may use Markdown within a line: **bold**, *italic*, `code`, links and [[glossary-id]]. Enter starts a new line. Lists and headings are not available here.

Move, resize and edit it on the preview

It works as for extra images, with two differences: a text box resizes freely (hold Shift to keep its proportions), and with the keyboard Alt+← / → change its width and Alt+↑ / ↓ its height. Double-click a text box, or press Enter on a selected one, to jump to its text in the Slide tab.

The box is the area of the fill and the border. Text that doesn't fit is still shown, outside the box: make the box larger, or the text smaller.

Its look

Font
The template's body, heading or code font, or a system or serif font.
Size
The template's size for small text, body text, a subtitle, a title or a hero title; or Custom…, a percentage of the slide width (2 is about body text).
B, I, U, AA
Bold, italic, underline, uppercase. Then the alignment: left, center, right, and top, middle, bottom inside the box.
Text color, Fill
Click a swatch from the template, or the last box for any other color. The crossed-out swatch means the template's text color, or no fill. Fill opacity makes the fill see-through, not the text.
Border, outline and padding
A border (width, solid, dashed or dotted, its color), Corners to round them (a large value makes a pill), Padding between the edge and the text, and a Text outline: a thin halo around the letters, so text stays readable on a photo. All in percentages of the slide width.
In audience mode
As for extra images: from the start, or on the next click (with an effect).

Every change is one step for Ctrl+Z. Find & Replace also finds and replaces text in text elements.

In reader mode and elsewhere

  • Readers see the text in place, can find it with search, and glossary terms in it open their definition. A slide with text elements stays a picture on a phone, like one with extra images.
  • Text elements are saved in show format 0.2, like extra images.
  • Converting a PowerPoint deck: text boxes that fit none of the layout's places become text elements at the same place, with their font size, colors, fill and border.

Picture styles

Any picture (in an image field, a card, a reader image block or an extra image) can get a picture style and an opacity. The styles come from the template, so they match its look; you only choose one.

StyleWhat it does
NoneThe picture as it is.
ShadowA soft drop shadow under the picture.
Soft edgesThe edges fade into the background.
Rounded cornersRounded corners.
FrameA white border with a small shadow, like a print. (Conclusion: with a thin magenta line.)

These are the styles of the shipped templates; another template can offer other ones.

Choose a style

Once a field has a picture, a row of small previews appears under it: None and one per style, each showing this picture in that style. Click one. The selected style has a blue outline, and the preview on the right changes at once.

Opacity

Drag the Opacity slider (or use the arrow keys on it) to make the picture partly transparent, in steps of 5 %. The value is stored when you let go; 100 % means fully visible. Use it for a picture behind text, or to tone down a decoration.

Good to know

  • Both are one step for Ctrl+Z.
  • With Show the whole image the shadow follows the picture; rounded corners and a frame follow the picture's box.
  • A frame adds a border inside the picture's box, so hotspots on a framed reader image can be a few pixels off. Check them in the preview.
  • If a show names a style its template doesn't have (for example after switching templates), the picture is shown without it and the field says so, with a Remove it button.
  • A show that uses a style or an opacity is saved in show format 0.2. That happens by itself.
  • Converting a PowerPoint deck: a picture's shadow, soft edges, rounded corners or outline becomes the matching style, and its transparency the opacity.

Many websites refuse to be embedded in another page. The editor warns about addresses that cannot work; check the preview for the rest.

Click-to-load. A page from another site does not load until the reader agrees: they see its title, the site and Open in new tab, plus a Load button. Nothing is sent to that site before the click, and after it other pages from the same site load directly until the tab is closed. Tick Load straight away, without asking the reader to skip the question for one page. Files in the show folder always load directly. The fallback image (optional, for example a screenshot of the page) replaces the card, and is what prints and what the show grid shows. A Mermaid diagram can have a fallback image too, set in show.json ("fallback": { "src": …, "alt": … }).

Allow the page to…. Embedded pages run in a sandbox: scripts, forms and pop-ups work, nothing else. Tick Full screen for a video player, Dialogs, Downloads or Presentation when a page needs them. Same origin lets a page from another site use its own cookies and logins (some sites need it to work at all); it is ignored for files in the show folder, because such a page could then reach the reader's notes. Once a page has loaded, Open in new tab ↗ appears below it, for sites that refuse to be shown inside another page.

Detail level
Essential (1), Standard (2) or Deep dive (3). A reader who chose depth 2 sees levels 1 and 2.
For
Click For: everyone and tick the reader profiles the block is meant for. None ticked: every reader sees it. Create profiles in Show settings.

More for the reader

Related slides
Slides offered as "see also" below this one. Add them from the list, reorder with ▲, remove with ✕.
Show the slide above its reader blocks
Untick it for a reader-only text page without the slide picture.
Hide this slide completely from reader mode
For slides that only make sense during a live talk, such as "Questions?".

Hotspots

Hotspots are numbered markers on the image of an Image with Hotspots block. Add the image first.

  • Place: click on the image. A marker appears and its title field gets focus, so you can type right away. Below the title, write the popup text in Markdown.
  • Move: drag a marker. With a marker selected, the arrow keys nudge it; with Shift in bigger steps.
  • Remove: Delete on the selected marker, or its 🗑.
  • Without a mouse: + Add hotspot places one in the middle of the image; then move it with the arrow keys.

A hotspot stays at the same spot on the image at every screen size.

Diagrams (Mermaid)

Slipr renders Mermaid diagrams natively in both audience and reader mode. Diagrams are written as plain text and rendered directly in the browser into lightweight, scalable SVGs using vendored Mermaid.

Where diagrams can be used

  • On a slide (Audience mode): select the Diagram layout. It provides a diagram slot for Mermaid code and an optional caption, plus a slide title.
  • In the reader layer (Reader mode): use a Diagram block ("type": "diagram") with Mermaid code and an optional caption.

Supported diagram types

All standard Mermaid diagram formats work out of the box, including:

  • Flowcharts: flowchart LR (left to right) or flowchart TD (top down) with rectangular nodes, round nodes, decision diamonds, database cylinders and subgraphs.
  • Sequence diagrams: sequenceDiagram with actors, participants, sync/async arrows and autonumbering.
  • State diagrams: stateDiagram-v2 for state machines and workflows.
  • Class diagrams: classDiagram for object and data structures.
  • Entity Relationship diagrams: erDiagram for database entities and relationships.
  • Git graphs, Gantt charts, Mindmaps and Pie charts.

Example: Flowchart

flowchart LR
    A[Authoring] --> S[(Show folder)]
    S --> V[Audience Mode]
    S --> R[Reader Mode]

Example: Sequence diagram

sequenceDiagram
    autonumber
    Author->>Editor: Edit slides & blocks
    Editor->>Show: Save show.json
    Audience->>Viewer: Open presentation

Key features

Offline and private
Mermaid is vendored inside Slipr (zero external CDN requests, zero tracking, works completely offline on trains, flights and conference Wi-Fi).
Theme matching
Diagram typography, backgrounds and borders match the active Slipr template tokens automatically.
Searchable
All labels, node names and notes inside diagrams are indexed by reader search (/) and editor Find & Replace (Ctrl+F / Ctrl+H).
Clear syntax errors
If your Mermaid definition has a typo, Slipr highlights the error with a friendly badge and the exact line number rather than breaking the slide.

Graphs

A graph shows how things relate: parts of a system, ideas, people, steps. You list the nodes (the boxes) and the links between them; Slipr places them by itself. While presenting, a graph can grow click by click; readers can explore it: drag it, zoom, click a node to read about it and jump to its slide, and filter by tag.

For now you write a graph in show.json (open it in a text editor such as VS Code; it suggests the field names as you type). The editor shows a summary such as Graph: 7 nodes, 8 links, 3 steps and draws the graph in the preview. Save in the editor first, and reload the show after editing the file by hand.

A graph on a slide

Add a slide with the Graph layout, save, and fill its graph slot in show.json:

"graph": {
  "nodes": [
    { "id": "show", "label": "show.json", "tags": ["format"],
      "md": "One file per show.", "slide": "s-data-1" },
    { "id": "template", "label": "Template", "tags": ["template"] },
    { "id": "viewer", "label": "Viewer", "tags": ["viewer"] }
  ],
  "edges": [
    { "from": "show", "to": "template", "label": "names" },
    { "from": "viewer", "to": "show", "label": "reads" }
  ],
  "steps": [
    { "show": ["viewer"] },
    { "focus": "show" }
  ]
}

The fields

nodes
One entry per box. id is required and must be unique (links and steps use it). label is the text on the box (default: the id). tags group nodes: the first tag picks the color. md is the text a reader sees after clicking the node (Markdown). slide is a slide id: the node gets a Go to slide link.
edges
The links: from and to (node ids; the arrow points to to), and an optional label on the line.
layout
How the nodes are placed: cose (the default: related nodes pull together), breadthfirst (a tree, top down, good for hierarchies and flows), concentric, circle or grid.
steps
Only on a slide, while presenting: one step per click, after the slide's own builds. { "show": ["id", …] } brings in those nodes (they are hidden until then; a link appears once both its ends are there). { "focus": "id" } zooms in on a node and its neighbours and dims the rest; the next show step zooms out again. Nodes no step names are there from the start. Going back a click undoes a step.
data
For a large graph: put the nodes and edges in their own file in the show folder, for example data/team.json containing { "nodes": [...], "edges": [...] }, and write "data": "data/team.json" instead of (or as well as) nodes and edges. The file travels with Export as one file.
caption
A line below the graph. The default template's Graph layout also has its own Caption field in the Slide tab.
fallback
An optional picture ({ "src": "images/graph.png", "alt": "…" }) for print and slide thumbnails. Without one, Slipr shows the nodes and links as a list, which is also what screen readers get.

A graph in the reader layer

A graph can also be a reader block, under a slide in reader mode. Add it to the slide's reader.blocks in show.json, with an id, "type": "graph" and an optional title, plus the same fields as above except steps. Like any block it can have for (profiles) and depth:

{ "id": "team-map", "type": "graph", "depth": 2, "title": "Who works with whom",
  "data": "data/team.json", "layout": "breadthfirst" }

Colors

You don't choose colors: the template does. Every tag gets the next color of the template's graph palette, in the order the tags first appear; nodes without a tag get the first color. In reader mode the tags appear as colored buttons that explain the colors and hide or show those nodes.

Checks

Mistakes show up under the preview (see Live preview and problems). Warnings: a node id used twice, a link or step that names a node that doesn't exist, a slide that doesn't exist and a data file that isn't there. Errors: a graph without nodes or data, a node without an id and steps on a reader block. The demo show has two examples: the slide How the pieces connect and the block on Backup: the show format (from data/show-format.json).

Rich text fields, lists, speaker notes and reader text use a small, safe Markdown. HTML is not allowed: it is shown as plain text.

The insert toolbar

Above every reader Markdown field, a small toolbar inserts the special parts for you:

  • Glossary term: pick a term; with words selected it becomes [[term|those words]]. See Glossary.
  • Popup: wraps the selected text in ^[…], or inserts an empty one to type into.
  • Slide link: pick a slide; the selected words become the link text.

Show settings

Click ⚙ Show at the top of the slide list. Click a slide to go back.

Metadata
Title, subtitle, author, date, language (a code such as en or nl), a short description (for the reader welcome and link previews) and tags.
Audience presentation settings
Aspect ratio (16:9 or 4:3), the slide transition (none, fade, slide, convex, concave, zoom, or Reveal's default), slide numbers, and an agenda slide before each chapter.
Chapters
Add, rename, reorder (▲ / ▼) and delete chapters, each with an optional summary. The agenda and the reader contents follow this order. Deleting a chapter tells you how many slides lose it.
Profiles
The kinds of readers, with an optional description that readers see when they choose. Deleting a profile tells you how many blocks were meant for it; a block meant only for that profile becomes visible to everyone.
Glossary
Terms with a Markdown definition and an optional link. See Glossary for how to add, use and delete them.
Reading routes
Curated routes for readers, such as a five-minute overview: a name, a description, and either all slides or a list of slides you put together and reorder.

A new item gets a placeholder name, selected so you can type over it. Names, titles and terms can't be left empty. An item's id is set when you create it and never changes, so references keep working when you rename it.

Glossary

The glossary explains the words your readers may not know. You write a term and its definition once; wherever you refer to the term, a reader can tap or hover it, or press Enter on it, to see the definition in a popup. In audience mode the same words are ordinary text, so the slides stay clean.

The dedicated Glossary Editor

Open the full-screen Glossary Editor by clicking 📖 Glossary in the toolbar, or 📖 Open Glossary Editor in Show settings. Press Esc anytime to return to your slides.

  • Split-view layout: the left sidebar lists all glossary terms with real-time search, category filters (All, In Use, Unused, No Def), and sorting (A → Z, Z → A, Most used, Least used).
  • Keyboard navigation: press ↑ and ↓ in the sidebar to move through terms; press Ctrl+N or + to create a new term.

Deck-aware word completion

When you add a new term or type a term name, Slipr scans your presentation (slides, titles, bullets, cards, speaker notes and reader blocks) for acronyms (like API or CSS), technical names (like Reveal.js or WebSocket), and recurring words. It suggests matching words in a dropdown as you type, complete with occurrence counts across your deck.

Click 💡 Deck suggestions in the glossary header to open the suggestions drawer: it lists frequently occurring terms across your deck that don't have glossary definitions yet. Click + Add on any suggestion to create a glossary entry in one click.

Edit and manage terms

  1. Term Name: type the term. Autocomplete offers words found in your presentation.
  2. Stable Identifier (ID): the short handle used in Markdown (such as [[reveal-js]]). You can rename the ID and click Rename ID: Slipr automatically updates all [[oldId]] occurrences across the presentation!
  3. Other names (Aliases): comma-separated plurals, acronyms or abbreviations, such as AI, A.I. for artificial intelligence. Reader mode automatically links these phrases on your slides.
  4. External Link: optionally provide a web address (starting with https:// or http://). Readers see a Learn more ↗ link in the popup.
  5. Definition (Markdown): write the definition. The toolbar above the field helps insert links and terms. Below the field, a Reader Popup Preview displays exactly how readers will see the popup.

See where a term is used and jump to slides

The Usage & References panel displays exact reference counts across the presentation: both explicit [[id]] Markdown links and text mentions of the term or its aliases. Click Jump to slide → next to any reference to jump directly to that slide in the editor.

A term that isn't referenced anywhere in the presentation is flagged with ⚠️ Unused / Orphaned, with a quick button to delete it safely.

Delete a term

Click 🗑 Delete term. A term that is not used is removed at once. For a term in use, the editor asks what to do with its references:

Delete, keep the words as plain text (unlink)
The references become ordinary text with the words readers saw. Usually what you want.
Delete, leave the references
The [[id]] references stay in the text, giving a warning until you define the term again.

Use a term in your text

  • With the toolbar: above reader text, tab text, hotspot text and glossary definitions, open [[ ]] Term… and pick the term. It is inserted at the cursor as [[id]], which shows the term's name.
  • With your own words: select words first, then pick the term. They become [[id|your words]]: the reader sees your words, and the popup still explains the term. Use this for plurals or other word forms, such as [[agent|agents]].
  • By hand: type [[id]] or [[id|words]] in any Markdown field, including slide text and speaker notes.

Terms on your slides

You don't have to mark terms on the slides themselves. In reader mode, Slipr finds the glossary terms in a slide's titles, text, bullets and cards and makes the first one of each clickable, with the same popup. It also finds a term under its Other names.

  • Whole words only, regardless of capitals and accents: Template and template both count, templates only if it is one of the other names.
  • The longest term wins: with both layout and layout picker in the glossary, the words layout picker open the second.
  • On the big screen (audience mode) the slides stay plain: no underlines, no popups.

What readers get

  • Terms in reader text are marked; tapping, hovering or pressing Enter opens the popup with the name, the definition and the optional link.
  • Terms on the slides are marked the same way, once per slide.
  • Reader search also finds glossary terms, under their other names too, and their definitions.
  • To try a popup yourself, click Read in the toolbar: it opens reader mode at the selected slide.

Problems

Warning: unknown glossary term "[[…]]"
The text refers to an id that is not in the glossary: a typo, or a deleted term. Correct the id, add the term, or remove the brackets.
The popup has no "Learn more" link
The link must start with https:// or http://.

Live preview and problems

The preview follows every change as you type.

Audience
The slide as it appears on the big screen, scaled to fit the pane.
Reader
The slide plus its reader layer. Choose a profile and a depth above the preview to see exactly what that reader gets.

A note above the preview tells you when the viewer will treat the slide differently: a slide hidden from the audience is shown after the last slide, without a number; a slide hidden from readers does not appear in reader mode.

Problems with the slide are listed under the preview:

  • Errors stop the show from opening in the viewer until they are fixed, for example an image block without an image.
  • Warnings point at things to improve, for example a required field that is empty, text too long for the layout, or missing alt text.

Find and replace

Press Ctrl+F or Ctrl+H, or click 🔍 Find & Replace. The search covers the whole show: slide fields and cards, speaker notes, reader summaries and blocks (including tabs and hotspots), and the show's metadata, chapters and glossary.

  • Tick Match case or Whole word to narrow the search.
  • Every match is listed with its place (for example Speaker notes or Card 2: title). Click a match to go to its slide.
  • Replace in Current Slide changes the selected slide only; Replace All changes the whole show. Either is one step to undo.

Present and Read

Present ▶ (F5)
Saves, then opens audience mode in a new tab at the selected slide. Press S there for the presenter view with notes, O for an overview of all slides.
Read
Saves, then opens reader mode in a new tab at the selected slide.

Both work for shows anywhere on disk: the viewer opens the same folder. If saving fails, or a show opened by address still needs its folder, the new tab closes again and the editor tells you why.

Export as one file

Export… saves the show as one HTML file that holds everything needed to present and read it: the show, its images, its template with fonts and illustrations, and the Slipr viewer. Whoever gets the file can open it with a double-click: no Slipr, no server, no internet, nothing to install.

When to use it

  • Presenting on another computer, or where the Wi-Fi can't be trusted: copy the file to a USB stick or the laptop.
  • Sending a show to someone to read in their own time: attach the file, or put it on a shared drive. They get the full reader mode.
  • Keeping a copy of a show as it was on a given day.

Export a show

  1. Fix any errors under the preview first: the exported file shows the same error page as the viewer would.
  2. Click Export… in the toolbar.
  3. Choose where to save the file. Its name is the show's id, for example demo.html; you can change it. In a browser without a save dialog the file goes to your downloads.
  4. Wait a moment while the editor packs the show. A message under the toolbar says where the file went and how big it is.

The export is the show as it is in the editor, with unsaved changes included. Exporting does not save the show itself; press Ctrl+S for that.

A show opened by its address (?show=…) can only be exported when it is inside the Slipr folder, like the demo. For a show elsewhere, open its folder with Open… first.

Open an exported file

  • Double-click it, or drag it into a browser window. Chrome and Edge are tested; other current browsers should work.
  • It opens in audience mode, ready to present: arrow keys to move, O for an overview of all slides.
  • For reader mode, press R (and A to go back), or add ?mode=reader to the end of the file's address. Readers can choose their profile and depth as usual.
  • Search, glossary popups, hotspots, tabs, diagrams and the reader's own highlights, notes and bookmarks all work offline. Those notes stay in the reader's browser on that computer.

What is in the file, and what is not

IncludedNot included
All slides and reader blocks, speaker notes, chapters, profiles, glossary and reading routes; the images the show uses; the template's fonts and illustrations; the viewer, and the diagram library when the show has diagrams Embedded https: sites (they still need an internet connection) and links to other web pages; images or files the show refers to that are missing from its folder (a message names them)

Expect a few MB: the fonts and images are inside. Large photos make the file large; see Images for keeping them small.

Changing an exported show

An exported file is a copy: it can't be opened in the editor. Change the show itself, then export again; give the new file a new name or replace the old one.

Messages

Export: show: images/… not found; left out
The show refers to a file that is not in its folder. Add the image again, or remove the reference, and export again.
Export: template: … not found
Part of the template is missing from Slipr's templates/ folder. The file still opens, but may look different.

More in Troubleshooting. The same export is available as a command for the Slipr folder: npm run export -- shows/<name>.

Undo, redo and saving

  • ↶ or Ctrl+Z undoes the last change; ↷, Ctrl+Y or Ctrl+Shift+Z redoes it. The editor remembers the last 100 steps.
  • Typing in one field counts as one step until you pause for a second. Dragging a hotspot or a slide is one step too.
  • Undo works for everything that changes the show, including deleting slides and replacing text. It does not delete image files that were copied in.
  • Saving: press Ctrl+S or click Save in the toolbar to write show.json to disk. Saving clears the dirty dot next to the title.
  • Autosave drafts & crash recovery: while you have unsaved changes, the editor automatically persists a draft to your browser's local storage (IndexedDB) every 5 seconds, as well as whenever you switch away or close the tab. If the browser closes unexpectedly or crashes, opening the show again displays a dialog offering to restore your unsaved draft. Restoring places your draft back into the editor with the pre-restore state available in the undo stack. Saving to disk or discarding the draft removes it from browser storage.
  • Undo history is lost when you reload the page. Saving does not clear it.

Troubleshooting

There is no Open… or New… on the start screen
Your browser lacks the File System Access API. Use Chrome or Edge.
"Allow access" appears after a reload or restart
Browsers forget folder permissions between sessions. One click on Allow access restores it; the browser only lets the editor ask after a click.
Save asks me to choose a folder
The show was opened by its address (?show=…). Pick the folder that contains its show.json; from then on it saves there.
Present or Read opens nothing
The browser may block the new tab. Allow pop-ups for the editor's address, and check the message bar for a save problem.
The show will not open in the viewer
It has an error. Errors are listed under the preview of the slide that has them, in red.
Export… does nothing, or nothing is saved
The save dialog may have been cancelled. Without a save dialog (some browsers) the file is downloaded instead: look in your downloads. A message under the toolbar reports where the file went.
The exported file stays on "Loading show…"
Open it in Chrome or Edge (tested); other current browsers should work too, but older ones cannot run it. If it still fails, export again and check the message bar for warnings about missing files.
An embedded page is empty in the exported file
Embedded pages from the show folder work only if they are self-contained; embedded https: sites need an internet connection, as always.
A message says the template was found by name
The show refers to its template by a path outside its folder. That's fine: the editor and viewer use the template with that name from Slipr's templates/ folder.
My text is cut off on the slide
The layout has a limit for that field; a warning says so. Shorten it, choose a layout with more room, or move the details to the reader layer.
An embedded page stays empty
The site does not allow being embedded. Before Load, readers can use Open in new tab on the card; after it they see an empty frame. Use a link in a text block instead.
A diagram shows a red "Diagram syntax error" box
There is a typo or unsupported syntax in the Mermaid code. The error box explains what line and token Mermaid could not understand. Check the syntax or test it in the Mermaid Live Editor.
